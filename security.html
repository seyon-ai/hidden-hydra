The Security Model

How Hidden Hydra keeps your words unreadable to everyone except the people you send them to — including us.

1 · Identity keys

When you join, your browser generates an ECDH P-256 key pair using the Web Crypto API.

  • The private key is stored only in your browser's local storage. It is never uploaded, never sent, never derivable from the server.
  • The public key is published on your profile document so friends can encrypt toward you.
  • Your profile page shows a fingerprint of your public key so you can verify it out-of-band.

2 · Direct messages

For a DM, both devices perform an ECDH key agreement: shared = ECDH(myPrivate, theirPublic). The shared secret is stretched with HKDF-SHA256 into an AES-256-GCM message key. Every message is encrypted with a fresh random 12-byte IV. Only the two participants can compute this key.

3 · Groups & world rooms

Where E2EE applies: direct messages and private groups. World lounges are public, moderated plaintext rooms by design — thousands of strangers can't perform key ceremonies, and public rooms need server-side moderation. Treat anything posted in a world lounge as public.

Private groups use a random room key per epoch. Every member's document groups/{room}/keys/{member} holds a map of wraps — one per epoch — each wrapped with an ephemeral ECDH exchange. Writes are merge-writes, so no device can ever destroy another epoch's wrap, and sharing is per-epoch: whenever a key-holder opens the room, they add wraps for every epoch each member is missing. Devices therefore converge on all epochs the moment both sides have been online once. Messages carry their epoch, so history you hold keys for stays readable after a re-key.

Honest limitations: if your browser storage is reset (or you switch devices), the private key that unwraps old epochs is gone — old messages then stay locked forever, by design; the chat shows one collapsed notice instead of a wall of locked bubbles, and a new epoch keeps the conversation flowing. If nobody who holds a room key comes online while you join, your client waits, then offers a new epoch.

4 · What is and isn't encrypted

  • Encrypted: message text, attached image references, reply quotes.
  • Not encrypted (metadata): sender id/name/emblem, timestamp, room id, reactions, typing indicators — the same metadata model used by mainstream E2EE messengers.
  • Not encrypted by design: the Hydra AI room (the AI must read your text to answer) and system/bot messages. These rooms are clearly labelled in the app.
  • Images: encrypted references; the uploaded file itself lives on imgbb's CDN. Don't attach images you wouldn't trust to a photo host.

5 · Secrets on the server

The Groq (AI) and imgbb API keys exist only as Vercel environment variables, used by the serverless functions /api/ai and /api/upload. Browsers never receive them. The Firebase web config in the client is a public identifier by design; access control is enforced by Firestore / Realtime Database security rules.

6 · Moderation & bans

Your own client asks the moderation model about outgoing world/group messages and applies strikes to its own profile (3 warnings → ban). Severe threats are banned instantly. Reports via /report are logged for human review. Because messages are E2EE, moderation sees only what your device voluntarily submits — exactly like the message author reading their own text.
